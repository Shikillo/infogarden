# Paso 2 - Crear un flujo de tareas/pantallas

> [!abstract] En una frase
> Es el segundo paso del proceso de prototipado, donde se dibuja un flujo de tareas o pantallas para entender cómo el usuario navega entre ellas.

## ¿Qué problema resuelve?
Permite visualizar y entender cómo el usuario se desplaza por el sistema, identificando posibles problemas de navegación o flujo de tareas antes de crear el prototipo.

## Qué es
El segundo paso del proceso de prototipado consiste en crear un flujo de tareas o pantallas. Esto implica tener una idea de cómo el usuario navega de una pantalla o página a la siguiente, y entender qué ocurre cuando el usuario hace clic en un widget (o por qué quiere hacer clic). Dibujar un flujo de tareas es una actividad escalable: puede abarcar una pequeña o una gran parte del sistema, o implicar a una persona o al equipo entero. Un flujo de tareas puede evolucionar según el diseño y el prototipo progresan a través de iteraciones.

## Cómo podrías haberlo descubierto
El material muestra que, a menudo, no es fácil conocer el flujo de tareas; debes comprender también el contexto en el que la tarea se desarrolla. Crear un flujo de tareas ayuda a visualizar y entender el flujo de usuario antes de prototipar.

## Ejemplo
> [!example]
> Un equipo dibuja un flujo de tareas para una aplicación de comida: pantalla principal → menú → selección de plato → confirmación de pedido. (Material, Tema 2, p. 10-11)

## Errores comunes
> [!warning]
> No dibujar un flujo de tareas, lo que lleva a un prototipo sin una estructura clara de navegación.
> No considerar el contexto en el que la tarea se desarrolla, lo que puede llevar a un flujo de tareas inapropiado.

## Autoevaluación
> [!question]- ¿Por qué es importante crear un flujo de tareas antes de prototipar?
> Permite entender cómo el usuario navega por el sistema y qué ocurre en cada paso, identificando problemas potenciales antes de crear el prototipo.
